## 数据与输入输出设计

- 20 Hz 控制，前视与腕部 RGB，策略图像初步为 256×256；展示视频使用独立外部视角。每条记录保存 frame index、模拟时间与单调墙钟时间。
- 原始轨迹保存观测 `s_t`、动作 `a_t`、动作后的观测 `s_{t+1}` 对齐关系；记录 action 前的图像，避免一步错位。保存 qpos/qvel、7 轴关节状态、EEF 位姿、夹爪开度、底座状态、语言、任务 ID、seed、初始 MuJoCo 状态和场景配置、上游版本。
- 当前 robosuite 动作空间是 12 维（EEF 位移/旋转、夹爪、底座、躯干和模式），原始数据记录完整动作。第一版适配已固定为 7 维臂/夹爪动作：OSC base 坐标系归一化 delta，正负1对应最大5cm位移/0.5rad旋转；夹爪+1关/-1开；其余补零并设模式-1。状态为7轴关节角+2指位置，共9维；见 `DATA_CONTRACT.md`。
- 模型 state 从可获得的本体感知组成；物体/抽屉真实位置、任务成功标记等特权状态只用于脚本示教和评测，不输入 π0.5。单抽屉不能验证“听懂目标选择”，必须在相同初始状态下交换两个目标语言指令测试。
- LeRobot Dataset 格式版本与训练器版本是两件事。独立 CPU 环境已用 LeRobot 0.4.4 官方 API 验证 v3.0 转换与加载：2条脚本轨迹830帧，以及独立的1条人工失败尝试1200帧，所有图像/状态/动作/语言/时间戳逐帧核对通过；这些是数据流水线样本，成功人工训练集尚待采集。服务器阶段另行核对 π0.5 trainer/处理器版本，不在本地安装模型训练栈。
- 远程协议保存 prompt、两张图和 state；返回 `[H, action_dim]` 动作块。执行前 k 步（候选 k=5，20 Hz），再更新图像并请求下一块。记录 H、k、延迟、丢帧和超时次数，禁止把离线逐帧预测称为闭环 rollout。

## 量化评测设计（尚未执行）

第一版预注册：每个任务 ID 条件 20 次、未见初始位置 20 次；固定种子清单、600 步 horizon 和20Hz控制频率。此前文档400步低于415步脚本时长，现统一到环境600步上限；键盘人工采集默认每1200步暂停提醒，可延长或取消限时，不作为模型评测预算。后续扩大样本量再谈稳定性能；同时报告成功数/总数与 Wilson 95% 区间。

沿用 RoboCasa 开抽屉归一化位移 ≥0.95、关抽屉 ≤0.05 的任务判据；额外记录连续维持 10 个控制步的稳定成功率。上游归一化基准为 `drawer.depth × 0.55`，并非整个滑轨范围。指定目标抽屉还要检查非目标抽屉没有误操作。收纳任务增加物体在抽屉内和最终关闭的判据，分别记录各阶段。

“未见初始位置”须有明确互不重叠的位置区间，不能仅换随机种子。训练、验证、测试按 episode/场景配置划分，禁止把同一轨迹帧随机切开；checkpoint 按验证集选择，保留测试集。脚本成功率、π0.5 成功率、ID、OOD、完整厨房与 Lite 必须分行报告。

## Checkpoint、展示与开源

每个 run 使用独立目录；保存训练配置、数据/代码版本、归一化统计、模型与处理器、optimizer/scheduler、RNG、step。部署使用完整模型与处理器目录，恢复训练使用完整 checkpoint；只导出权重不足以保证重现。先验证短训练和恢复，再扩展训练量。

视频角标区分 `SMOKE_ZERO_ACTIONS`、`SCRIPTED / privileged state`、`PI05 / checkpoint=...`；注明播放速度、seed、任务和是否剪辑。README 无模型结果时写“未训练/未评测”，不填预期成功率，不把脚本视频作为 π0.5 推理。

上游实现和资产不复制成个人原创；记录 RoboCasa、robosuite、MuJoCo、LeRobot、π0.5 和两个参考工程的来源/许可。GitHub 只放代码、锁定配置、小结果和演示，不上传环境、缓存、完整数据、权重、密钥或服务器地址。正式选取数据时还需核对数据来源、版本及再发布许可。
